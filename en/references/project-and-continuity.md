# Project and Continuity

Load for serials, multi-character work, cross-session production, or handoffs. Every asset should trace to accepted facts and explicit input versions.

## Layers of truth

- **Project:** format, audience, delivery specs, world rules, and protected decisions.
- **Character:** identity, look state, injury, props, knowledge, and voice.
- **Shot:** time, location, screen direction, eyeline, action entry/exit, light, and sound edits.
- **Asset:** path, source, tool, parameters, seed, references, rights, version, and review state.
- **Candidate:** unapproved ideas and generations; never treat them as canon.

Use [the project overview](../templates/manga-project.md), [character bible](../templates/character-bible.md), [shot list](../templates/shot-list.md), and [asset ledger](../templates/asset-ledger.md).

## Naming and versions

Use stable IDs such as `E01`, `E01-S001`, `CHAR-01`, `LOOK-01`, `LOC-01`, `PROP-01`, and `AUD-001`.

```text
E01-S001_CHAR-01_LOOK-01_keyframe_v003_approved.png
E01-S001_motion_v002_candidate.mp4
```

Prefer `draft / candidate / approved / rejected / superseded` over “final-final.” Record approver and date.

## Before generation

Confirm the project, brief, and dependency versions; compare the prior shot exit with the current entry; load only relevant character, look, location, prop, and voice facts; stop when approved sources conflict.

Commit only accepted results. When hair, wardrobe, injury, prop, chronology, or layout changes, list every dependent shot and asset before deciding the regeneration scope.

The minimum handoff package contains the brief, relevant facts, input versions, output specs, rights constraints, complete/unverified items, failure record, and acceptance criteria.
