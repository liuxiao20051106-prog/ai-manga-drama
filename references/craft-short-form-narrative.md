# 短格式叙事与单集节奏

在写剧本、改单集结构、诊断「前几秒留不住人」「观众中途划走」「每集像流水账」时读取。SKILL.md 已内置底线（每场有目标/阻力/变化/后果、结尾留动力），此处是完整展开。

> 相关：分镜怎么把节奏落到镜头上见[镜头语言与分镜](craft-shot-language.md)；台词与旁白的字数预算见[台词、配音与声音](craft-dialogue-voice-and-sound.md)；连载与季播的长线设计见[商业化与分析](commercialization-and-analytics.md)。

## 一、短格式的本质是注意力预算

观众不是"看完"，而是**每秒都在决定要不要继续看**。把单集当成一条预算曲线：

| 区间 | 观众在问 | 必须给的东西 |
|------|----------|--------------|
| 0–3 秒 | 这是什么？值得停吗？ | 冲突、异常、或强情绪画面（不要世界观、不要人物介绍） |
| 3–15 秒 | 发生了什么？ | 人物 + 目标 + 阻力一次性交代清楚 |
| 15 秒–70% | 接下来呢？ | 每 5–10 秒一个信息增量或小转折（不要连续平淡） |
| 最后 20% | 结果是什么？ | 兑现本集回报（一个明确的变化） |
| 结尾 3 秒 | 然后呢？ | 钩子：悬念／反转／情绪余韵／选择 |

**不要机械套用固定秒数**。上面是参考节奏，实际取决于题材、平台和语速；但"开头不要铺垫、中段不要停滞、结尾不要收干净"这三条是通用的。

## 二、单集的三种结构模板

1. **悬念前置型**（最适合竖屏冷启动）
   异常画面/结果先给 → 回溯怎么走到这一步 → 结尾再掀一层。
   `结果钩 → 过程 → 更大疑问`
2. **问题—解决型**（最适合日常、治愈、搞笑）
   一个具体的小麻烦 → 尝试与受挫 → 用人物特质解决 → 代价或余韵。
   `麻烦 → 两次失败 → 转折 → 解决`
3. **递进揭露型**（最适合悬疑、规则类）
   线索 A → 结论 1 → 发现不对 → 线索 B 推翻结论 1 → 新结论。
   `推理 → 推翻 → 再推理`，每次推翻都是一个小回报。

## 三、一集只交付一个「变化」

事件堆砌 ≠ 故事。每集结束时要能回答：**什么从 A 变成了 B？**

- 关系变化：陌生 → 信任；信任 → 破裂
- 处境变化：安全 → 被追踪；欠债 → 被逼到绝境
- 认知变化：以为对方死了 → 认出他还活着
- 情绪变化：希望 → 绝望（或反向）

填不出 A→B 的这一集，要么合并，要么删掉。用[单集任务卡](../templates/episode-brief.md)的第一行走廊字段强制自己写出来。

## 四、钩子的四种类型

结尾钩不是"没讲完"，而是**给观众一个非看下一集不可的理由**：

| 类型 | 做法 | 例 |
|------|------|----|
| 悬念型 | 结果延后揭晓 | 他打开盒子，脸色变了——画面切黑 |
| 反转型 | 推翻观众刚才的认知 | 一直以为的好人摘下了面具 |
| 情绪型 | 情绪停在最尖锐处 | 她终于开口，却说了一句最伤人的话 |
| 选择型 | 停在选择的那一刻 | 电话响了两声，他的手悬在接与不接之间 |

进阶：**打断式**（真相说到一半被外力打断）、**倒计时式**（给出明确时限，章末时间只剩一点）、**反套路式**（所有人都以为他会退，他偏不）。

**钩子必须由剧情自然产生**。为了悬念而故意隐瞒观众已经看见的信息，会被当成剪辑错误而不是悬念。

## 五、台词与信息密度预算

- 中文配音常见语速约 **4–5 字/秒**（情绪激动或搞笑可更快）。据此倒推每集可容纳的**有效台词字数**：30 秒 ≈ 90–130 字，60 秒 ≈ 180–250 字。
- 超过预算就要砍。**砍台词永远比加快语速好**——语速一快，情绪就没了。
- 一集里交给"画面"的信息越多，能留给"台词"的就越少；先问"这条信息能不能用一个动作或一个道具说清"。

## 六、留存曲线诊断

拿到后台数据或自评时，按掉点位置反推病因：

| 掉点位置 | 大概率病因 | 最小修复 |
|----------|------------|----------|
| 前 3 秒 | 开头是风景/介绍/标题卡 | 换成冲突画面或异常状态 |
| 3–15 秒 | 人物和目标交代不清 | 用一句台词把"谁、要什么、被什么挡住"说完 |
| 中段 | 连续平淡，没有信息增量 | 插入小转折或新信息，或压缩整段 |
| 70% 处 | 观众已经猜到结果 | 提前把回报给掉，把结尾留给新问题 |
| 结尾 | 钩子太软或收得太干净 | 换钩子类型；把最后一个镜头改成"未完成"状态 |

## 七、连载：单集闭环 + 长线问题

- **单集闭环**：新观众从任何一集进来都能看懂——本集有自己的问题与解决。
- **长线问题**：老观众追更的理由——三到五个贯穿全季的悬念或承诺，登记在[项目总览](../templates/manga-project.md)里，每集推进一点。
- **承诺台账**：埋下的每条线索都要记录「埋设集 → 计划回收集」。挖坑不填是掉粉最快的做法。
- 同时活跃的支线不超过三条；完成一条再开一条。
- 做季播时，季末要有比单集更强的收束与更大的新问题（见[商业化与分析](commercialization-and-analytics.md)）。

## 八、竖屏对叙事的约束

- 画幅窄，**人物必须更靠近镜头**；信息不要横向铺开（三个并排的人挤在竖屏里都会变小）。
- 上下留白是资源：上部放标题/状态，下部放字幕，中段才是叙事区。
- 视线引导以纵向为主（俯视、仰视、从上到下的动作）。
- 竖屏里"动作规模"看起来更大，克制使用大场面；小动作 + 更近的景别更有效。

## 九、常见失败模式

| 症状 | 病因 | 修法 |
|------|------|------|
| 像流水账 | 只有"然后"，没有"因此" | 补因果：让前一个动作导致后一个后果 |
| 平淡 | 没有阻力，人物太顺利 | 加时间压力、加代价、加对手 |
| 看不懂 | 信息给得太散或太晚 | 前 15 秒集中交代人物+目标+阻力 |
| 结尾软 | 事件办完了才结束 | 停在后果或选择上，而不是停在"收工" |
| 每集一样 | 用同一模板机械复制 | 轮换结构模板与情绪类型 |
| 太赶 | 一集塞了两集的内容 | 拆集；宁可留白也不要压缩情绪 |

## 十、写前自检

- [ ] 前 3 秒有画面冲突或强情绪吗？
- [ ] 前 15 秒交代了人物、目标、阻力吗？
- [ ] 这一集的 A→B（变化）是什么？
- [ ] 中段每 5–10 秒有信息增量或转折吗？
- [ ] 台词字数在语速预算内吗？
- [ ] 结尾是四种钩子之一，且由剧情自然产生吗？
- [ ] 本集推进了至少一条长线问题吗？
- [ ] 新观众能看懂这一集吗（单集闭环）？
