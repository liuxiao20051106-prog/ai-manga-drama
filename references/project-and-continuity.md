# 项目与连续性管理

在连载、多角色、多场景、多人协作或跨会话制作时读取。目标不是堆积笔记，而是让每个资产都能追溯到已确认事实和输入版本。

## 事实源分层

- **项目事实**：类型、受众、发布规格、世界规则和不可改事项。
- **角色事实**：身份锚点、造型状态、伤势、道具、知识和声音。
- **镜头事实**：时间、地点、轴线、视线、动作入口/出口、光线与音频接点。
- **资产事实**：文件位置、来源、工具、参数、种子、参考图、权利、版本和审核状态。
- **候选项**：未批准的设计、提示词和试生成结果，不得写成正式事实。

使用[项目总览](../templates/manga-project.md)、[角色 Bible](../templates/character-bible.md)、[分镜表](../templates/shot-list.md)和[素材台账](../templates/asset-ledger.md)。

## 命名与版本

推荐编号：`E01`、`E01-S001`、`CHAR-01`、`LOOK-01`、`LOC-01`、`PROP-01`、`AUD-001`。文件名可采用：

```text
E01-S001_CHAR-01_LOOK-01_keyframe_v003_approved.png
E01-S001_motion_v002_candidate.mp4
```

版本状态使用 `draft / candidate / approved / rejected / superseded`，不要用“最终版2”“真的最终版”。每个批准状态记录确认人和日期。

## 写前/生成前检查

1. 确认当前项目、任务卡和依赖资产版本。
2. 读取上一镜头出口状态和本镜头入口状态。
3. 只装配相关角色、造型、场景、道具和声音资料。
4. 标记冲突、缺失和未经批准的新事实。
5. 输入不完整或两个批准版本冲突时停止，不凭模型记忆选择。

## 回填与变更传播

只回填作者接受的结果。角色发型、服装、伤势、道具、时间或场景布局一旦改变，列出受影响的后续镜头和资产；先决定重做范围，再修改依赖项。

保留失败资产及失败原因可以减少重复尝试，但失败资产不得混入交付目录。未公开素材、密钥、合同、身份证明和完整声音样本不进入普通运行日志。

## 交接包

每个制作单元的最小交接包包括：任务卡、相关事实、输入资产及版本、输出规格、权利限制、已完成项、未验证项、失败记录和下一位负责人的验收标准。
